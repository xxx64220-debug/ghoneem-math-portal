## Safe application and verification

`apply.sql` is generated by `build_sql.py`. It locks each question and key, checks
the exact before content, track and PostgreSQL asset hash, and records before/after
content and assets in the existing audit log. A conflicting record aborts the whole
transaction. Exact replay is a no-op; changes after application cause replay to
abort. The SQL never deletes or reinserts questions, changes tracks or lessons,
changes exam membership, or recalculates saved responses/results. All five existing
holds in this remainder and the earlier ambiguous-coefficient holds are preserved.
